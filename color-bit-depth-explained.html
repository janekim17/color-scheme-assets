Color bit depth explained: 8-bit, 16-bit and smoother gradients

Image dimensions tell you how many pixels you have. Bit depth tells you how many values can describe each channel in those pixels.

By Color Scheme Studio · October 29, 2026

More steps between colours, rather than more pixels.

Higher bit depth can preserve finer numerical differences during editing. It does not automatically make an image sharper, enlarge its colour gamut or repair a damaged gradient.

Start with one RGB channel

An RGB pixel has red, green and blue components. In a conventional 8-bit-per-channel image, each component can hold 256 integer values, from 0 to 255. The “8” refers to the number of binary digits used for one channel, not a list of eight colours.

Combining the three channels gives 256 × 256 × 256, or 16,777,216 possible RGB combinations. This is why the same image may be described as 8 bits per channel or 24-bit RGB. Those labels count different things: one channel versus three channels together. An additional alpha channel is separate from that RGB count.

Six-digit HEX notation is a convenient way to write those three 8-bit RGB channel values. Each pair runs from 00 to FF. For example, #808080 sets all three channels to 128. The notation describes the values; a defined colour space, commonly sRGB on the web, gives them their colour meaning.

Why can a smooth gradient develop bands?

A gradient needs a sequence of closely spaced tones. If there are too few distinct values across a large transition, adjacent areas can form visible steps. This is often called banding or posterization. Gentle skies, blurred backgrounds and large shadow transitions can make the issue easier to notice than a busy texture does.

Not every band comes from the source image’s bit depth. Compression, strong adjustments and the display path can also affect what you see. Before changing the whole workflow, compare the editable source with the exported file at the same viewing size. If the source is smooth and the export is not, examine the export settings first.

Keep precision while making adjustments

Higher-bit-depth working files provide more numerical room for processing. A large tonal adjustment can stretch a narrow range of values across a wider range. With limited precision, that can leave gaps between tones; having more precision during the work can reduce rounding and quantization problems.

When you have a high-bit-depth source and expect substantial colour or tonal work, keeping that precision through the editable master is useful. Make a delivery copy for the destination rather than reducing the only master early in the process. The appropriate export depends on the format and where the image will be used; a website asset and a production editing file serve different purposes.

Changing an existing 8-bit file to a higher-bit-depth mode does not recover tones already lost. It can give subsequent operations more precision, but it cannot reconstruct the original scene’s missing information. Likewise, raising a bit-depth setting is not a reliable one-click cure for banding already baked into a compressed file.

Separate precision, gamut and resolution

These three ideas answer different questions. Resolution concerns the number of pixels. Colour gamut concerns the range of colours a colour space or device can represent. Bit depth concerns the available numerical precision within an encoding. More precision does not, by itself, move the outer boundary of a colour space.

A larger-gamut image can still have limited precision, and a high-bit-depth file can still use a familiar gamut. Avoid choosing settings from one impressive number alone. Check the source, the adjustments you need to make and the requirements of the final destination.

A practical sequence is to preserve the best available source, work at suitable precision, then inspect the actual exported result. For a palette graphic, check the flat swatches and any gradients separately. Flat colours may look unchanged while a long gradient reveals the cost of an aggressive adjustment or export.
